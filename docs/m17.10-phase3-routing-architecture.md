# RYVEN 3.0 — M17.10 Phase 3: Intelligent Multi-Model Dynamic Router & Controlled Fallbacks

## Overview
Milestone 17.10 Phase 3 upgrades the authoritative `ModelRouter` into a deterministic, measurable, policy-aware multi-model router with bounded fallback. It provides deterministic task classification, lightweight explainable complexity estimation, a single bounded provider-health tracker with configurable circuit breakers, and bounded fallback (hard-capped at depth 1) at the model execution boundary.

---

## 1. Deterministic Routing & Explainability (`router.py`, `models.py`)
- **Core Performance Objective**: Fast local inference by default (`qwen2.5:7b`); remote reasoning only when explicitly permitted, enabled, and privacy-validated.
- **Deterministic Heuristics (`estimate_task_complexity`)**:
  - Classifies task complexity (`LOW`, `MEDIUM`, `HIGH`), context size requirement, and latency sensitivity without secondary LLM invocations.
  - Heuristics inspect prompt token bounds, code snippet syntax (`def`, `class`, `SELECT`), algorithmic problem-solving keywords (`dynamic programming`, `recursion`, `optimization`), complex reasoning keywords (`step-by-step`, `mathematical proof`), and structured JSON schema complexity.
- **Explainable Routing Decisions (`RoutingDecision`)**:
  - Extended compatibly with stable machine-readable reason codes:
    - `LOCAL_DEFAULT`: Assigned standard local-first workhorse (`qwen2.5:7b`).
    - `TASK_CAPABILITY_MATCH`: Specialized capability match (e.g., local vision models `moondream` / `llava:7b` for `VISION` tasks, OCR models for `OCR`).
    - `REMOTE_EXPLICITLY_ALLOWED`: Authorized high-complexity reasoning on remote endpoint.
    - `EXPLICIT_PREFERENCE`: Explicit user preference fulfilled.
    - `CIRCUIT_OPEN`: Target provider tripped open; safely routed to local fallback.
    - `PRIVACY_POLICY_BLOCKED`: Remote inference requested, but privacy scan detected sensitive credentials/tokens; remained local.
    - `FALLBACK_SELECTED`: Controlled fallback route assigned.
  - Carries `fallback_eligible`, `fallback_model`, `fallback_provider`, `estimated_complexity`, `context_size_requirement`, `latency_sensitive`, and `health_summary`.

## 2. Provider Health & Circuit Breakers (`health.py`)
- **Bounded Telemetry (`ProviderHealthTracker`, `ProviderHealthRecord`)**:
  - Thread-safe (`threading.RLock`) in-memory tracking of successes, failures, timeouts, rate limits, consecutive failures/successes, and last failure type.
  - Bounded latency history (`deque(maxlen=50)`).
  - Uses monotonic clock (`time.monotonic()`) for precise elapsed duration measurement.
  - Zero leakage: never records prompts, responses, credentials, or raw exception strings in telemetry.
- **Configurable Circuit Breaker (`CircuitBreaker`)**:
  - Consecutive-failure threshold: default 3.
  - Cooldown duration: default 60.0s.
  - States: `CLOSED`, `OPEN`, `HALF_OPEN`.
  - Half-open recovery probing: deterministic transition after cooldown; allows a single probe call.
  - Success resets the breaker to `CLOSED` and resets consecutive failure counters.
  - Failure in `HALF_OPEN` immediately returns state to `OPEN`.
  - Non-retryable client errors (such as `AuthenticationError` or `SecurityViolationError`) do not trip the circuit breaker.

## 3. Controlled Fallback Execution (`router.py`, `unified.py`)
- **Execution Boundary (`ModelRouter.execute`, `ModelRouter.stream`)**:
  - Centralizes multi-model execution and automated fallback; consumers do not duplicate retry/fallback logic.
- **Eligibility & Error Normalization**:
  - Eligible for fallback: `ProviderUnavailableError`, `ProviderTimeoutError`, `RateLimitError`.
  - Non-eligible (fail-fast, no retry): `AuthenticationError`, `SecurityViolationError`, `ProviderInvalidRequestError`, `asyncio.CancelledError`.
- **Invariants**:
  - Maximum fallback depth strictly capped at 1.
  - Cycle prevention: primary provider cannot fall back to itself; fallback providers cannot cascade to another fallback.
  - Fallback-disabled configuration respects `fallback_enabled=False` or `max_fallback_depth=0`.
  - Safe diagnostics: original error code preserved in response metadata (`fallback_occurred`, `fallback_from_provider`, `fallback_reason_code`).
- **Streaming Fallback Safety**:
  - If user-visible text has already begun emitting (`visible_chunks_emitted > 0`), the router **never** switches providers mid-stream. It terminates immediately with a normalized `StreamEventType.ERROR` chunk and raises the exception.
  - Fallback is only permissible prior to any visible chunk emission (e.g. immediate connection failure or pre-stream timeout).
