# RYVEN 3.0 — Milestone 17.10 Phase 4: ModelSecurityGateway & Privacy Boundary Enforcement

## Architecture Overview

Phase 4 establishes an authoritative, fail-closed security gateway (`ModelSecurityGateway`) through which every local and remote AI execution request must pass. The gateway controls model inference boundaries exclusively and does not alter or weaken downstream tool execution controls (`SafetyGuard`, `CapabilityPermissionManager`, `ConfirmationManager`).

```
Consumer
   │
   ▼
ModelRouter (Deterministic Route Selection)
   │
   ▼
ModelSecurityGateway (Authoritative Policy & Privacy Boundary)
   │  ├── Privacy Mode Enforcement (LOCAL_ONLY, PRIVACY_FIRST, BALANCED, MAX_REASONING)
   │  ├── Sensitive Data Scanning & Structured Redaction
   │  ├── Interactive Confirmation Verification (Replay Defense)
   │  └── Pre-Stream Chunk Boundary Sanitization
   │
   ▼
ProviderAdapter (Normalized Provider Abstraction)
   │
   ▼
Provider Transport (Ollama Local / Grok Remote / HF Remote)
```

## Validated Privacy Modes

1. **LOCAL_ONLY**:
   - Permits local providers only (`OLLAMA`, `HUGGINGFACE_LOCAL`).
   - Remote requests return normalized, sanitized `SecurityViolationError` (`PRIVACY_POLICY_DENIAL`).
   - No silent cloud upgrades or fallback.

2. **PRIVACY_FIRST** *(Secure Default)*:
   - Local inference is strictly preferred.
   - Remote inference is blocked by default unless explicit trusted authorization is bound to the request via verified `ConfirmationManager` tokens.
   - Sensitive content must never be sent remotely; requests with detected secrets are blocked (`SENSITIVE_CONTENT_BLOCKED`).

3. **BALANCED**:
   - Local inference remains preferred.
   - Remote inference is permitted when explicitly authorized (`allow_remote=True` and policy opt-in), request is eligible, and sensitive data has been safely redacted.
   - Prohibited root credentials (private keys) strictly block remote dispatch.

4. **MAX_REASONING**:
   - Permits stronger remote reasoning when authorized.
   - Applies the same secret scanning, redaction, and auditing.
   - Cannot override security denials.

## Sensitive Data Scanning & Redaction

The gateway catalog detects:
- API Keys: xAI (`xai-`), OpenAI (`sk-`), Anthropic (`sk-ant-`), GitHub (`ghp_`, `gho_`, `github_pat_`), AWS (`AKIA`, `ASIA`), Hugging Face (`hf_`).
- Bearer tokens (`Bearer ...`).
- Passwords and client secrets (`password=...`, `client_secret=...`).
- Session cookies and auth tokens (`cookie=...`, `sessionid=...`).
- Private keys (`BEGIN ... PRIVATE KEY`).
- Database URLs containing embedded credentials (`postgres://user:pass@host:port/db`).
- Confirmation tokens (`CONF-...`).
- Environment variable and `.env` references.

Harmless text and standard code syntax are preserved without destructive blanket redaction.

## Interactive Confirmation & Replay Defense

- Reuses RYVEN's existing `ConfirmationManager`.
- Binds authorization tokens to specific request operations (`provider`, `model_id`).
- Tokens are one-time use; consumed tokens are tracked in `_consumed_confirmation_tokens` with thread-safe `RLock`.
- Invariants:
  - Model output (`role == "assistant"`) can NEVER approve remote execution.
  - Memory context (`metadata["source"] in ("memory", "semantic_memory", ...)`) can NEVER grant authorization.
  - Confirmation tokens embedded within prompt text are rejected as untrusted injection attempts.

## Streaming Safeguards

- Pre-stream validation executes before the first network connection or byte is opened.
- `StreamChunkSanitizer` cleans delta text incrementally.
- Split `<think>` tags and secrets spanning chunk boundaries are sanitized without leakage.
- On abort, cancellation, or transport failure, internal sanitizer buffers are wiped to prevent flushing unsafe trailing fragments.

## Audit Events & Telemetry

- Publishes normalized `ActionEvent` instances to `action_bus`:
  - `MODEL_SECURITY_EVALUATION`
  - `MODEL_SECURITY_ALLOWED`
  - `MODEL_SECURITY_DENIED`
  - `MODEL_SECURITY_REDACTED`
  - `MODEL_SECURITY_CONFIRMATION_REQUIRED`
  - `STREAM_SECURITY_TERMINATED`
- Audit records contain safe metadata only (provider, model_id, privacy_mode, redaction counts, timestamps).
- Prompts, responses, and secrets are strictly excluded from event telemetry.
- Telemetry failure enforces a documented fail-closed policy (`SECURITY_EVALUATION_FAILURE`).
