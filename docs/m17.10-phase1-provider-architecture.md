# RYVEN 3.0 — M17.10 Phase 1: Core Multi-Model Provider Architecture

## Overview
Milestone 17.10 Phase 1 introduces a provider-neutral model execution layer for RYVEN 3.0. It defines standard contracts, schemas, error hierarchies, and thin provider adapters without altering existing consumers, routing semantics, or safety boundaries.

---

## 1. Provider Abstraction
The core contract is defined in `backend/app/ai/contracts.py`:
- **`ProviderAdapter` (ABC)**:
  - `provider_id`: Returns canonical `ModelProvider` enum.
  - `generate(request: AIRequest) -> AIResponse`: Executes inference asynchronously with normalized request and response types.
  - `health_check() -> Dict[str, Any]`: Reports operational telemetry without exposing credentials.
  - `is_available() -> bool`: Evaluates live readiness of the provider.

---

## 2. Normalized Data Models

### `AIRequest`
- Provider-neutral model input.
- Fields:
  - `messages`: List of structured `ChatMessage` items.
  - `system_prompt`: Optional high-level instructions.
  - `model_id`: Target model tag or repo identifier.
  - `temperature`: Sampling temperature ($[0.0, 2.0]$).
  - `max_tokens`: Token generation ceiling.
  - `timeout_seconds`: Execution budget.
  - `structured_output_schema`: JSON schema dictionary for structured outputs.
  - `images`: Transient base64 string payloads (never exposed in `__repr__` or logs).
  - `task_type`: Cognitive classification (`TaskType`).
  - `metadata`: Execution metadata (recursively sanitized against credential leaks).
  - `stream`: Boolean indicating streaming delivery preference.

### `AIResponse`
- Uniform output schema across all providers.
- Fields:
  - `content`: Text response generated by the model.
  - `model_id`: Canonical model identifier.
  - `provider`: Provider enum or string identifier.
  - `finish_reason`: Termination reason (`stop`, `length`, etc.).
  - `usage`: `AIUsage` token accounting.
  - `latency_ms`: Round-trip execution latency in milliseconds.
  - `request_id`: Correlation tracking ID.
  - `metadata`: Sanitized provider execution details.
  - `model`: Property alias providing backward compatibility with legacy consumers.

### `AIUsage`
- Non-fabricated token metrics:
  - `prompt_tokens`: Tokens in input.
  - `completion_tokens`: Tokens in output.
  - `total_tokens`: Total tokens consumed (safely computed if only components are provided).
  - Supports `None` safely when provider does not expose token telemetry.

## 3. Normalized Error Hierarchy
All model errors derive from `AIProviderError` and carry stable machine-readable codes with automatic secret redaction:
- `ProviderUnavailableError` (`PROVIDER_UNAVAILABLE`): Provider daemon or endpoint unreachable.
- `AuthenticationError` (`AUTHENTICATION_FAILED`): Missing or invalid credentials.
- `ContextOverflowError` (`CONTEXT_OVERFLOW`): Context window budget exceeded.
- `RateLimitError` (`RATE_LIMIT_EXCEEDED`): HTTP 429 or rate limits enforced.
- `SecurityViolationError` (`SECURITY_VIOLATION`): Security policy blocked dispatch.
- `ProviderTimeoutError` (`PROVIDER_TIMEOUT`): Execution timed out.
- `ProviderInvalidRequestError` (`INVALID_REQUEST`): Malformed request parameters.
- `ProviderResponseError` (`PROVIDER_RESPONSE_ERROR`): Malformed or unparseable payload.

---

## 4. Provider Adapters (`backend/app/ai/adapters.py`)
- **`OllamaAdapter`**:
  - Wraps `OllamaProvider` (default: `qwen2.5:7b`).
  - Preserves offline execution and localhost socket transport.
  - Normalizes token counts and maps timeouts and network errors.
- **`GrokAdapter`**:
  - Wraps `GrokProvider` (model: `grok-2-latest`).
  - Strictly opt-in; missing `GROK_API_KEY` marks provider unavailable without application crashes.
  - Sanitizes all exceptions, metadata, and responses.
- **`HuggingFaceAdapter`**:
  - Wraps `HuggingFaceLocalProvider` and `HuggingFaceRemoteProvider`.
  - Distinguishes local vs. remote based on profile and preference.
  - Reports unavailable if local weights are not cached (no background downloads).

---

## 5. Model Registry & Router Compatibility
- **`ModelProvider.GROK`** added to enum alongside `OLLAMA`, `HUGGINGFACE_LOCAL`, `HUGGINGFACE_REMOTE`.
- `grok-2-latest` profile added to `ModelRegistry` catalog as disabled and remote by default.
- `ModelRouter` recognizes `ModelProvider.GROK` when explicitly preferred and remote inference is authorized. Default local Qwen routing for reasoning, planning, and coding is completely unchanged.

---

## 6. Scope Boundaries & What Phase 1 Does NOT Implement
- **Phase 1 DOES NOT**:
  - Modify consumer components (`assistant.py`, `llm_planner.py`, `vision.py`).
  - Implement full streaming pipelines (owned by Phase 2).
  - Implement intelligent/cost-optimized routing or fallbacks (owned by Phase 3).
  - Implement `ModelSecurityGateway` or privacy modes (owned by Phase 4).
  - Implement provider telemetry & metrics pipelines (owned by Phase 5).
  - Perform consumer unification (owned by Phase 6).
  - Install PyTorch/Transformers or trigger automatic model downloads.
